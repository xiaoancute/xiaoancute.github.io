# 在手机上写博客（Termux）

不用记一堆命令，在 Termux 里用 `pnpm blog` 打开菜单，数字键选操作即可。

---

## 一、Termux 第一次配置（只做一次）

> Termux 里 `./xxx.sh` 这种直接执行**经常因权限被挡**（共享存储不给文件加执行位）。**全程只用 `pnpm blog`**，它不需要执行位、不依赖 shell 脚本，就没这个问题。

### 1. 装 Termux 和基础工具

从 [F-Droid](https://f-droid.org/packages/com.termux/) 装 Termux（别用 Play 商店那个，已停更）。打开 Termux 后：

```sh
pkg update && pkg upgrade -y
pkg install -y nodejs git
```

> 注意：Termux 的 `nodejs` 包自带的是新版 Node，能满足博客要求的 Node ≥ 22。装好后 `node -v` 看一眼版本。

### 2. 装 pnpm

```sh
npm install -g pnpm@11
pnpm -v
```

> 项目会兼容 pnpm 11 的小版本差异，不需要手动对齐到某个精确版本。

### 3. 克隆你的博客仓库到 Termux 家目录

**一定要克隆到家目录 `~` 下**，不要放 `/sdcard` 或 `/storage`——共享存储下的目录不能加执行位、也不能正常跑脚本（这正是你遇到的权限问题的根源）。

```sh
cd ~
git clone https://github.com/xiaoancute/xiaoancute.github.io.git blog
cd blog
```

### 4. 开始使用

```sh
pnpm blog
```

第一次运行时助手会自动安装依赖，之后日常只用这一条命令。**首次配置到此结束。**

## 二、日常写博客（每次都这样）

### 启动博客小助手

```sh
cd ~/blog
pnpm blog
```

会出现菜单：

```
博客小助手
公开 N  草稿 N  N 个未提交文件
1. 写一篇新草稿
2. 写一条动态/微语
3. 管理微语（编辑/删除/置顶/位置）
4. 编辑文章信息
5. 公开或隐藏文章
6. 删除文章（移入隔离区）
7. 启动本地预览
8. 运行完整检查
9. 提交并发布
10. 快速同步（仅提交推送小改动）
0. 退出
请选择:
```

数字键选择，回车确认，`0` 退出。下面逐项说明。

---

### 1. 写一篇新草稿

填几个：文章标题、文件名、一句话简介、分类、标签（逗号分隔）。其它默认就行。建出来是**草稿**——本地预览能看到，正式网站不会显示。

### 2. 写一条动态/微语

输一句话（支持 Markdown 语法），自动带时间戳生成一条动态消息发布到网站上。

### 3. 管理微语（编辑/删除/置顶/位置）

写好的微语想改字、撤回、置顶或加位置用这个。先列出最近的微语（最新在上，最多 30 条），选一条后：

- **编辑正文** — 回显当前正文，回车保留，输新内容覆盖
- **置顶 / 取消置顶** — 置顶的微语会带 📌 标记
- **位置** — 填了会显示在微语旁（如"广西"），留空则清除
- **删除** — 确认后直接删文件

微语超过 30 条时，列表底部的"搜索更早的"可按正文关键词查找。

### 4. 编辑文章信息

先列出文章选一篇，然后逐项改：

- **标题** — 回车保留旧值，输入新值则覆盖
- **一句话简介**
- **分类**
- **标签**（逗号分隔）
- **封面图** — 选项：留空 / 随机封面(api) / 手动输贴址 / 从 public 目录里选图
- **是否置顶**
- **自定义 slug**（留空用文件名当网址）
- **语言** — 用于 `<html lang>` 和 SEO。候选来自项目启用的语言（en/zh_CN/zh_TW/ja/ko/ru 等），留空则用站点默认语言；也可手动输入 code
- **密码** — 留空是公开文章；填了密码会在构建时加密（AES-256-GCM），访客需输密码才能看。填了密码还会再问一句**密码提示**（访客可见）

每项都显示当前值，**回车 = 保留原样**，输新值 = 覆盖。改正文请用 MT 管理器等文件编辑器直接改 `.md` 文件。

### 5. 公开或隐藏文章

切 `draft` 开关。草稿→公开会自动更新"上次编辑时间"。公开→草稿则从网站隐藏，本地预览还可见。

### 6. 删除文章（移入隔离区）

不想保留的文章用这个删掉——**不是真删**，文件会被移到 `src/content/_quarantine/` 目录（Astro 不构建这里，网站上看不到），需要时可手动放回原位恢复。选文章后要确认两次。删完记得用第 10 项（快速同步）推上去。

### 7. 启动本地预览

启动开发服务器，浏览器访问 `http://localhost:4321` 看效果。**按 Ctrl+C 停止**。（同一局域网的电脑也能访问你手机这个地址预览。）

### 8. 运行完整检查

跑 Biome + Astro + TypeScript + 生产构建。**手机上一般用不到**——检查交给 GitHub 即可，你本地不用跑（下面第 9 条说明）。

### 9. 提交并发布

正式发内容用这个。流程是：

1. 先列出改动给你看
2. 问你「这些都要发布吗？」确认
3. 问要不要先跑完整检查 — **手机上选"快速发布"跳过**就行
4. 填提交说明（默认 `content: update blog`，可改）
5. 自动 `git add` + `git commit` + `git push origin master`

推送后 GitHub 自动构建部署，几分钟后网站更新。

### 10. 快速同步（改点小配置用这个）

只改了点 `siteConfig.ts` 之类的小配置、不想走第 9 项那些确认步骤时用这个：

1. 直接问提交说明（默认 `chore: update config`，回车就用）
2. 自动 `git add` + `git commit` + `git push`

**比第 9 项少三步**：不看改动列表、不二次确认、不检查。推完收工。

### 0. 退出

## 三、关于 git 命令

`pnpm blog` 菜单里那些"提交/发布/同步"本质都是 `git` 干活——`git add` + `git commit` + `git push`。**你不用手敲 git**，菜单选项帮你跑。想手敲也行：

```sh
git add --all
git commit -m "chore: update config"
git push origin master
```

效果和第 10 项「快速同步」一模一样。

## 四、推送后会发生什么

```
你点菜单第10项  →  git push 推到 GitHub  （手机这边几秒）
                      ↓
GitHub Actions 自动构建部署（几分钟，在 GitHub 服务器上）
                      ↓
网站几分钟后更新
```

手机只负责推代码，**编译在 GitHub 上自动跑**，你不用管。如果部署失败 GitHub 会发邮件告警。

## 五、那个权限问题怎么破

- 不要在 `/sdcard`、`/storage`、内部存储下跑仓库——这些地方文件不能加执行位，脚本和部分工具会报 `Permission denied`。
- 仓库放 `~/blog`（Termux 家目录）下就没这问题。
- **永远用 `pnpm blog`**——它直接用 node 跑，不需要执行位，绕开所有 shell 脚本权限问题。
